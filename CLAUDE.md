## Commands

```bash

# template and runs the exported program, which needs the Godot export templates
# Summary: logs/godot-<path|exported>-summary.txt

scripts/godot-web-test.sh [--threads]

# Sync test data from ../sdk-go to tests/testdata and tests/override
scripts/sync-testdata.sh

# Regenerate tests/enums and tests/conf (run in ../whisper)
DIAGNOSTIC=0 just sdk-gd

# Generate the overview-gd, sdk-gd, gen-gd and gen-gd-editor pages into ../docs/archmage (doctool XML converted by
# docs/gdscript-docs.mjs) and stage the docs repo; then build there with pnpm build
docs/update.sh

# Set Archmage.VERSION in addons/archmage/archmage.gd and commit it
scripts/bump-version.sh [--yes] <version>

# Release with relstep (progress in release.json, not committed): tests in both modes, CHANGELOG.md, bump and tag.
# It does not push; pushing a v* tag runs .github/workflows/release.yml, which tests on Linux and publishes the zip
scripts/release.sh <version>
```

Set `GODOT` to override the Godot executable (default `/Applications/Godot_mono.app/Contents/MacOS/godot`). Pass `TRACE=1` to a script to trace it.

## Architecture

**Archmage** is a GDScript configuration management SDK for loading JSON-based game configs in Godot 4.6 or later. It is pure GDScript and needs no C#. The repository root is a Godot project, so the SDK, the tests and the demo run in one project.

| Path | Content |
|---|---|
| `addons/archmage/` | The SDK. Users replace this directory to upgrade. It is not an editor plugin |
| `addons/archmage_editor/` | The editor plugin generated by the `godot-editor-gd` template of `../whisper`; used by the demo |
| `tests/` | The test runner and test scripts. `testdata/` and `override/` are synced from `../sdk-go/internal`; `golden/` is the expected output; `conf/` is generated code (`json-gd` template); `enums/` is generated by `enum -t gd`; `handconf/` is a hand-written conf for the SDK tests |
| `scripts/` | Test and sync scripts |
| `logs/`, `builds/` | Output of `scripts/godot-test.sh`; not committed, and hidden from Godot by `.gdignore` |

The synced data and the generated code are committed. `.gitattributes` marks everything except `addons/archmage/` as `export-ignore`, so the Asset Library zip contains only the SDK. `addons/archmage_editor/` is excluded because it references the classes in `tests/conf`.

### Tests

- Test scripts are the files named `*_test.gd` under `tests/`, except in `testdata/`, `override/` and `golden/`. Each extends `res://tests/test_case.gd`, and each method named `test_*` is one test. The runner creates a new instance of the script for each method and awaits it on the main thread.
- GDScript has no exceptions, and `assert` is stripped from release exports. A test reports a failure with `check` or `check_eq` of `test_case.gd`. The runner also registers a `Logger` (`OS.add_logger`) and fails the running test on any logged error, such as `push_error` or a script runtime error. A test that expects errors calls `capture_errors()` and then `take_errors()`, which returns the messages to assert on. The release template does not log script runtime errors, so in `--exported` mode only `push_error` and engine errors fail a test; run the project directory mode to catch the rest.
- The runner lists `res://tests` instead of keeping a list of scripts. In an exported program the listing shows `x.gd.remap` or `x.gdc` for a script; the runner maps both back to `x.gd`.
- The runner prints a summary and exits with 0 only when at least one test ran and all passed. It accepts `--filter <regex>` (matched against `script.method`, such as `archmage_test.test_version`) and `--summary <file>` after `--`.
- From the project directory, `scripts/godot-test.sh` passes `res://tests/test_runner.tscn` as the scene to run. The release template does not accept a scene path, so `--exported` exports the preset `macOS (tests)`, whose feature `archmage_tests` selects `run/main_scene.archmage_tests`, the runner. `scenes/main.tscn` is the main scene without that feature.
- The preset needs `include_filter="*.json"` (Godot does not export JSON files by default) and `import_etc2_astc=true` in `project.godot` (required for arm64 and universal macOS builds). The script checks the export log for `ERROR`, because Godot can exit with 0 when an export fails.
- The script runs `--import` before every run, so that `class_name Archmage` is registered.
- `tests/conf_test.gd` loads `tests/testdata` with the generated code in `tests/conf`. `tests/golden/<case>/` holds its canonical output for each of the 10 golden cases of the Go SDK; the test also compares the values with `../sdk-go/internal/golden/<case>/`, where `null` equals an empty array or object. The Go golden files are read only in the project directory mode; the exported program skips the comparison. To rewrite the files, run `ARCHMAGE_UPDATE_GOLDEN=1 scripts/godot-test.sh --no-sync`. In `../sdk-go`, `go test ./internal -run TestPorting -porting` compares `tests/golden` with the Go golden files as well.
- `tests/handconf/golden/<case>/` holds the canonical output of the hand-written conf for each load case of `atlas_loader_test.gd`. Its values match `../sdk-go/internal/golden` on the fields that the hand-written conf has. To rewrite the files, run `ARCHMAGE_UPDATE_GOLDEN=1 scripts/godot-test.sh --no-sync`.
- An async test sets `_use_threads = false` on the loader or the `I18n` to run the path for platforms without thread support; in a build without thread support, it stays `false` for every test, and the tests that check worker threads are skipped. `scripts/godot-web-test.sh` runs all tests in a Web build: the presets `Web (tests)` and `Web threads (tests)` have the feature `archmage_tests`, and the harness serves them with the COOP/COEP headers that a build with thread support needs. A function that awaits `load_atlas_async()` resumes inside the call that completes the load, which still references the atlas; a test that checks that the atlas is freed awaits a frame first. GDScript does not let a function start a coroutine without awaiting it, so a test that needs a load running in the background starts it with `call_deferred`.

## Conventions

### SDK naming

- `addons/archmage/archmage.gd` declares `class_name Archmage`, the only global class name of the SDK. Other SDK scripts have no `class_name`; `archmage.gd` attaches each as a constant, such as `const Duration = preload("duration.gd")`. The path is relative, so the addon can be placed in any directory.
- Generated code and user code refer to `Archmage.Duration` and `Archmage.MinMax` without `preload`.
- An SDK script that uses its own type declares it first, such as `const Duration = preload("duration.gd")` inside `duration.gd`. Without it, `-> Duration` fails with `Could not find type "Duration"`.
- Document the SDK with `##` comments. `godot --doctool` names a script without `class_name` by its path (`lib/duration.gd`), so the docs conversion must rename it to `Archmage.Duration`.

### Generated config code (`json-gd`)

The template is `archmage/structs/tpls/json-gd.tpl` in `../whisper`. It uses no `--namespace`, and it outputs no `@tool` and no code that affects the runtime; discuss with the user before breaking this.

- Every generated type is a `RefCounted` class with typed fields and `static func from_json(d)`. Field names and file names are snake_case (`critRate` becomes `crit_rate`, `hero_table.gd`).
- When a field name, after the snake_case conversion, is a GDScript keyword that cannot be a variable name, `json-gd` appends `_` (`class` becomes `class_`), and archmage prints a warning with the field, its source and the new name. In Godot 4.6.3, `var class`, `var func` and `var signal` are parse errors; `var match` and `var name` are not. The list is `calc::fieldName` in the template. By the user's decision, `json-gd` handles no other name conflict: a field named `int`, `script` or `to_json`, or a pubtype named like a native class such as `Timer`, makes the generated file fail to parse, and a field named like a global function, such as `exp`, gets a `shadowed_global_identifier` warning in the editor.
- An inner class has the name that json-cs gives it: a private type keeps the prefix of its scope (`Hero_TalentsEntry`), so that it never hides a native class. A reference to a type that another file defines, such as a pubtype or the entry type of another table, is qualified with that file's class name (`ItemTable.ItemCfg`).
- Generated local variables and parameters start with `_` (`_d`, `_x`, `_e1`, `_atlas`), so that they never shadow a field.
- `archmage.gd` holds the JSON conversion functions (`J.i`, `J.f`, `J.s`, `J.b`) and `J.missing` for bind errors; each generated file has `const J = preload("archmage.gd")`. `atlas_version.gd` returns the version info at codegen time, read through `ConfigAtlas.code_version()`.
- An enum field is annotated with the enum type (`SdkEnum.HeroClass`, the class name of `enum.gd.tpl`) and `@warning_ignore("enum_variable_without_default")`, and is assigned with `as`.
- A regular table can be iterated over its config entries: `for hero in atlas.hero_table`.
- A duration, datetime, minmax or vector field is never `null`: `from_json(null)` gives the zero value, as the value types of Go do. A wtpool or tuple field is `null` when the JSON value is `null`, as the pointers of Go are.
- `Archmage.Vec2/3/4`, `MinMax`, `WeightedPool` and `Tuple` have untyped elements; their `from_json` takes a `Callable` that converts each element, such as `Archmage.MinMax.from_json(v, J.i)` or `Archmage.Tuple.from_json(v, [J.s, Archmage.Duration.from_json])`. Godot vectors are converted by `J.v2`, `J.v2i` and so on, and rgba by `Archmage.Rgba.from_json`.
- A ref inside a wtpool or tuple: the SDK object keeps the config ID in `_ref_ids` and `null` in `items`; the generated `_bind_refs` sets `items[i]`, and `_unbind_refs()` of the SDK object sets the ref items back to `null`. `to_json` writes `_ref_ids`.
- Each config source generates one `.gd` file. Its file-level `class_name` is the top-level type, named as in C# (`HeroTable`, `GameCfg`, `ChapterArray`, `RouteTable`); the other types are inner classes (`HeroTable.HeroCfg`).
- A regular table is a wrapper class that holds `var entries: Dictionary[int, HeroCfg]` and provides `lookup` (reports an error when the entry is missing), `try_lookup` (returns `null`), `has`, `size` and iteration.
- A config ID is a plain `int` or `String`. A wrapper object cannot be a `Dictionary` key, because GDScript compares objects by identity.
- A ref field holds the entry, such as `var weapon: ItemTable.ItemCfg`, and is `null` when the ID is the zero value. The ID is `weapon.id`. This works because loading fails when a non-zero ID has no entry.
- `atlas_extension.gd` is generated only when it does not exist; users edit it.
- `l10n.gd` (`class_name L10n`) is generated when a config has an l10n field, as in Go and C#. The user sets the static `Callable` vars `get_i18n` and `get_preferred_language`; `L10n.text(key)` returns the text in the preferred language, or the key when no language has it, and `L10n.get_text(key, lang)` returns `null` then. An empty key gives `""`. When a `Callable` is not set, they call `push_error` and return the key or `null`. A lambda that is still in either var when the process exits makes Godot 4.6.3 abort, so a test that sets a lambda resets the var to `Callable()`, and the docs tell users to set methods or static functions.
- Types map as follows: all integers to `int`; float types to `float`; string, path and origin to `String`; enum to `int` annotated with the generated enum type; bitflags to `int`; ref and backref to the entry type; backref-n to `Array[entry type]`; l10n to `String`; rgba to `Color`; duration to `Archmage.Duration` (nanoseconds in an `int`); datetime to `Archmage.DateTime` (unix time and zone offset, written back as `+01:00`); minmax, wtpool and tuple to `Archmage.MinMax`, `Archmage.WeightedPool` and `Archmage.Tuple` with untyped elements.
- A vector uses `Vector2/3/4` or `Vector2i/3i/4i` when the elements are 32-bit (float32, int32, or `ARCHMAGE_FLOAT_BIT_SIZE`/`ARCHMAGE_INT_BIT_SIZE` of 32), and `Archmage.Vec2/3/4` (with `to_godot()`) otherwise, as `cs-godot-vector` does.
- `[]T` is `Array[T]` and `map[K]V` is `Dictionary[K, V]`. Godot typed collections cannot nest, so the inner collection is untyped.

### Generated code contract

The SDK side is documented in `addons/archmage/atlas.gd` and `atlas_item.gd`. `tests/handconf/` is a hand-written conf in the shape that `json-gd` must generate; its class names have the prefix `Hand` (`HandConfigAtlas`) so that they do not collide with `tests/conf`.

- `ConfigAtlas` extends `Archmage.Atlas` and implements its abstract methods:
  - `atlas_items() -> Dictionary[String, Archmage.AtlasItem]` returns the same dictionary on every call. Each item is `Archmage.AtlasItem.new(hero_table, Archmage.AtlasItem.MAPPING_UNIQUE)` (or `MAPPING_VARIANT`, `MAPPING_MANY`), where `var hero_table := HeroTable.new()` is created empty with the atlas. The loader fills it in place; a skipped item stays empty.
  - `set_data_version(version: Archmage.VersionInfo)` stores `version` in `data_version`; it is `null` when atlas.json has none.
  - `bind_refs() -> String` resolves the refs of all tables. It returns `""`, or, for the first non-zero ID without an entry, a message that locates the ref, such as `hero[3].weapon: ItemTable: config entry not found for ID 999`. The loader then returns `ERR_INVALID_DATA`.
  - `on_loaded() -> String` returns `extension.on_loaded(self)`. `AtlasExtension.on_loaded(atlas: ConfigAtlas) -> String` returns `""` or an error message, which makes the loader return `FAILED` with that message.
  - `unbind_refs() -> void` calls `_unbind_refs()` of each table, which sets every ref field of the entries and of their nested objects to `null` and clears every array and dictionary of refs. `Archmage.Atlas` calls it on `NOTIFICATION_PREDELETE`; without it, entries that reference each other are never freed. A call to a method of the atlas itself fails there ("on a null instance"), so `unbind_refs` calls only methods of the objects it holds.
- The object of each item has these methods:
  - `load_json(data: Variant) -> String`. The loader merges all files and overrides of the item as parsed JSON and calls `load_json` once with the result. A `null` or missing value gives the default. `load_json` does not set the IDs of the entries. The asynchronous loader may call it on a worker thread. It returns `""`, or, for the first invalid value, a message that starts with the path of the value in the item, such as `[3].respawn: invalid duration "abc"`; the loader then returns `ERR_PARSE_ERROR`.
  - `apply_keys() -> void`, only in regular tables, sets the ID of each entry from its key. The loader calls it after `load_json` when the object has it, as Go and C# call `ApplyKeys`; the asynchronous loader calls it on the same worker thread.
  - `to_json() -> Variant` returns the content with the JSON keys of the config files (`critRate`), for `Archmage.canonicalize` and the golden files. It may return nested objects that have `to_json()`, `Color` and Godot vectors. A ref is written as its config ID, the zero ID when it references nothing. The generated code writes the config ID that `from_json` read, so the output does not change after `unbind_refs`.
- `from_json` keeps the ID of a ref in a private field (`_weapon_ref`), and a collection of refs as a collection of IDs of the same shape (`_starter_items_ref`). `_bind_refs` looks up the entries and rebuilds the collections of entries.
- Invalid values are reported through `Archmage.ParseError`, without shared state, so that `load_json` can run on a worker thread. The generated `load_json` creates a local `_e` and passes it to every `from_json(_d, _e)`; a value type calls `_e.fail(msg)`. After each field that can hold an invalid value (a duration, datetime or rgba, also inside objects, collections, minmax, wtpool and tuple), the generated code returns `_e.at(".field")`, which adds the segment to the front of the path; a collection loop adds `[index]` or `[key]` and breaks, and `load_json` returns `_e.message_at(segment)`. The SDK containers call `conv.call(value, e)` and add `.min`, `.items[i]` or `.item<i>`, so `J.i`, `J.f`, `J.s` and `J.b` take an unused `_e`, and every generated `from_json` has the `_e` parameter. Integers and other wrong JSON types are not validated.
- The generated `load_json` of an object that has refs calls `_unbind_refs()` first. Without it, the old entries of an atlas that is loaded again in place reference each other and are never freed.
- `lookup` of the zero ID returns `null` without an error, as in Go.

### JSON and integers

- The loader parses with `JSON.new().parse()`. Godot 4.6.3 parses every number as `float`, so generated code converts integers with `int(v)` and does not validate them.
- An integer above 2^53 in absolute value loses precision, and a uint64 above the int64 range cannot be represented. Document this limit.
- All float values in `tests/testdata` and `tests/override` are exact in float32, so Godot vectors do not break golden comparison. A value such as 0.1 added later needs handling, because the Go porting comparison is strict on float64.

### Error handling

GDScript has no exceptions, so the SDK follows the conventions of the Godot API.

- As with `JSON.parse()`, `load_atlas()` and `load_atlas_async()` return an `Error` code, `OK` on success. `get_error_message()` of the loader returns the message, which includes context such as the file path and the field path. A non-zero ID without an entry during BindRefs is a load failure.
- As with `get_node()` and `get_node_or_null()`, `lookup` calls `push_error` with the table name and the ID and returns `null`; `try_lookup` returns `null` without an error.
- Where Go panics, such as `WeightedPool.sample` on an empty pool, the SDK calls `push_error` and returns `null` or `-1`.
- When the JSON value of a value type is invalid, such as `"#FFF"` for rgba, the load fails with `ERR_PARSE_ERROR`, as in Go and C#. The message gives the item and the path, as the bind_refs messages do, and Go's wording for the value: `hero[2].themeColor: invalid RGBA string "#FFF"`. Called without a `ParseError`, as from user code, a value type calls `push_error` and returns the zero value.
- The class description of `addons/archmage/atlas_loader.gd` lists the error code of each kind of failure.

### Loading

- `load_atlas(atlas_file, cfg_root, atlas, options = null)` takes its arguments in the order of Go and C#, and resolves the paths in atlas.json against `cfg_root`.
- The default logger prints each message with `print`, after `INF `, as the C# `DefaultLogger` does; `Archmage.NullLogger` discards the messages.
- `load_atlas()` does all work on the calling thread. `load_atlas_async()` reads, parses and converts on `WorkerThreadPool`, runs BindRefs and OnLoaded on the main thread, and is used with `await`.
- `load_atlas_async()` reads atlas.json in one task, then runs one task per item, at most max concurrency at a time, polling the tasks once per frame. The atlas modifier and the logger run on the main thread. After the first failure, no task starts, and the running tasks are still waited for. The tasks use only their job objects (`_AtlasFileJob`, `_ItemJob`) and the item's object; the options that they read are copied when the load starts.
- Both must work in Web exports. Without thread support (`OS.has_feature("threads")` is false), the async API loads one item per frame on the main thread; without a `SceneTree`, it loads everything in one call.
- A loader runs one load at a time, and an atlas is loaded by one loader at a time (`Archmage.Atlas._loading`); otherwise the load returns `ERR_BUSY`.
- The load options are logger, FS, atlas modifier, whitelist, blacklist, variant, override root, override FS and max concurrency.
- `Archmage.I18n` behaves as the I18n of the Go and C# SDKs (`l10n.json`, `l10n.<lang>.json`, fallback). A language is a plain string. `merge_l10n_file` and `merge_l10n_data` return an `Error` code and set `get_error_message()`, as the loader does, and merge nothing on failure. `merge_l10n_file_async`, used with `await`, reads and parses on a `WorkerThreadPool` task and merges on the main thread; without thread support it runs on the main thread. `get_text` returns `null` for a missing key; `text` returns the key.
- The SDK does not register texts with `TranslationServer`: l10n keys are config data read through `L10n.text`, and `tr()` differs from `I18n` (it takes the fallback language from the project settings and treats `""` as missing).

### Editor plugin (`godot-editor-gd`)

- The `sdk-gd` recipe generates it into `addons/archmage_editor/`. It writes `plugin.cfg` and `archmage_editor_plugin.gd` only when they do not exist, so edit those two here; this copy loads `res://tests/testdata` and registers display formatters for hero and race. To change the other files, edit `../whisper/archmage/structs/tpls/godot-editor-gd.tpl`. `project.godot` enables the plugin, and the root node of `scenes/main.tscn` (`scenes/main.gd`) exports the config ID properties that it shows as dropdowns.
- The plugin mirrors `godot-editor-cs`: the configs are loaded when the Inspector first shows an object, the Tool menu item "Reload Game Configs for Editor" loads them again, and `_initialize_cfg_id_choices` registers the choices with `CfgIdChoices.register_defaults(atlas)` and `CfgIdChoices.register_<table>(table, format)`.
- Only `cfg_id_prop.gd` has a `class_name` (`CfgIdProp`), because game code uses it; the editor scripts preload each other. Only the EditorPlugin, EditorInspectorPlugin and EditorProperty scripts have `@tool`.
- A single config ID property is marked with `@export_custom(CfgIdProp.HINT, CfgIdProp.HERO)` and has the type `int` or `String`; an array uses `CfgIdProp.HERO_ARRAY` and has the type `Array[int]` or `Array[String]`. `HINT` is `PROPERTY_HINT_NONE`; the array editor of Godot reads the element type from the hint string and passes `PROPERTY_HINT_NONE` and the part after `:` to the editor of each element. Do not use `PROPERTY_HINT_TYPE_STRING`: without the plugin, Godot edits a `String` property with that hint as a class name, and clicking it crashes the editor.
- `_enter_tree` and `_exit_tree` of `archmage_editor_plugin.gd` call `CfgIdInspectorPlugin.rebuild_inspector()`, because the Inspector keeps its property editors when a plugin is enabled or disabled.
- Godot reports no warnings for scripts under `res://addons` by default (`debug/gdscript/warnings/directory_rules`). To check the plugin for warnings, use a copy of the project with the rules set to `{"res://": 0, "res://addons/archmage_editor": 1}` and each warning set to 2, and run `godot --headless --editor`.
- A `@tool` EditorPlugin can call a non-`@tool` `RefCounted` script in the editor: `static func`, `new()` and instance methods all run.
