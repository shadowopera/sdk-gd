# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
# Run the tests from the project directory; --exported exports the "macOS (tests)" preset with the release
# template and runs the exported program, which needs the Godot export templates
# Summary: logs/godot-<path|exported>-summary.txt
scripts/godot-test.sh [--no-sync] [--exported] [--filter <regex>]

# Export the tests for Web with the standard (non-.NET) editor and run them in headless Chrome; --threads exports
# the build with thread support. Needs /Applications/Godot.app (or GODOT_STANDARD), its Web export templates,
# Chrome (or CHROME) and node. Summary: logs/godot-<web|web-threads>-summary.txt
scripts/godot-web-test.sh [--threads]

# Run the tests in all four modes, in this order: project directory, exported, Web and Web with threads; it stops
# at the first mode that fails
scripts/run-all-tests.sh [--no-sync]

# Sync test data from ../sdk-go to tests/testdata and tests/override
scripts/sync-testdata.sh

# Regenerate tests/enums, tests/conf and addons/archmage_editor (run in ../whisper)
DIAGNOSTIC=0 just sdk-gd

# Generate the overview-gd, sdk-gd, gen-gd and gen-gd-editor pages into ../docs/archmage (doctool XML converted by
# docs/gdscript-docs.mjs) and stage the docs repo; then build there with pnpm build
docs/update.sh

# Generate addons/archmage/README.md from README.md, without its image and without "## Development" and what follows;
# --check fails when the copy is not up to date
scripts/sync-addon-readme.sh [--check]

# Set Archmage.VERSION in addons/archmage/archmage.gd and commit it
scripts/bump-version.sh [--yes] <version>

# Release with relstep (progress in release.json, not committed): addon README, tests in both modes, CHANGELOG.md, bump
# and tag.
# It does not push; pushing a v* tag runs .github/workflows/release.yml, which tests on Linux and publishes the zip
scripts/release.sh <version>
```

Set `GODOT` to override the Godot executable (default `/Applications/Godot_mono.app/Contents/MacOS/godot`). Pass `TRACE=1` to a script to trace it.

## Architecture

**Archmage** is a GDScript configuration management SDK for loading JSON-based game configs in Godot 4.6 or later. It is pure GDScript and needs no C#. The repository root is a Godot project, so the SDK, the tests and the demo run in one project.

| Path | Content |
|---|---|
| `addons/archmage/` | The SDK. Users replace this directory to upgrade. It is not an editor plugin |
| `addons/archmage_editor/` | The editor plugin generated by the `godot-editor-gd` template of `../whisper`; used by the demo |
| `tests/` | The test runner and test scripts. `testdata/` and `override/` are synced from `../sdk-go/internal`; `golden/` is the expected output; `conf/` is generated code (`json-gd` template); `enums/` is generated by `enum -t gd` |
| `scripts/` | Test and sync scripts |
| `images/` | The image of `README.md`; hidden from Godot by `.gdignore`. It is the same file as in the other SDKs; `../sdk-cs/docs/update.sh` copies it to the docs site, so `docs/update.sh` does not |
| `logs/`, `builds/` | Output of `scripts/godot-test.sh`; not committed, and hidden from Godot by `.gdignore` |

The synced data and the generated code are committed. `.gitattributes` marks everything except `addons/archmage/` as `export-ignore`, so the release zip, which `git archive` builds, contains only the SDK. `addons/archmage_editor/` is excluded because it references the classes in `tests/conf`.

`addons/archmage/README.md` is generated and committed; edit `README.md`, then run `scripts/sync-addon-readme.sh` (`scripts/release.sh` runs it too). The Asset Store requires a README inside the addon directory. The user submits each release to the Asset Store by hand, with the release zip.

### Related repositories

| Repository | Content |
|---|---|
| `../sdk-go` | The reference implementation. Its `internal/testdata` and `internal/override` are the source of `tests/testdata` and `tests/override`; `internal/porting_test.go` compares the golden files of all SDKs |
| `../sdk-cs` | The C# SDK. Several parts follow it, such as `FileAccessFS`, the JSON merge, the default logger and the editor plugin (`godot-editor-cs`) |
| `../whisper` | The `archmage` tool. The templates `json-gd.tpl` and `godot-editor-gd.tpl` are in `archmage/structs/tpls/` |
| `../docs` | The documentation site; `docs/update.sh` generates the GDScript pages into it |

whisper has two copies of `addons/archmage`: `archmage init -l gd` adds one to the projects it creates, and the tests of `archmage/examples/output/gd` use the other. After a change to `addons/archmage` or `json-gd.tpl`, update them in whisper: run `archmage/cmd/internal/conv.sh`, which copies the SDK and sets `SdkGdVersion`, then `just struct-gd`, which regenerates `examples/output/gd/conf`. A project that `archmage init -l gd` creates fails to parse when its generated code needs a newer SDK than the copy.

### Tests

- The tests use a runner written here (`tests/test_runner.gd`), not GUT, so that they also run in an exported program.
- The runner fails a test on any error that the engine or a script logs. The release template does not log script runtime errors, so in `--exported` mode only `push_error` and engine errors fail a test; run the project directory mode to catch the rest.
- The `macOS (tests)` preset needs `include_filter="*.json"`, because Godot does not export JSON files by default, and `project.godot` needs `import_etc2_astc=true`, which arm64 and universal macOS builds require.
- `tests/conf_test.gd` loads `tests/testdata` with the generated code in `tests/conf`. `tests/golden/<case>/` holds its canonical output for each of the 10 golden cases of the Go SDK; the test also compares the values with `../sdk-go/internal/golden/<case>/`, where `null` equals an empty array or object, because a typed array cannot be `null`. The Go golden files are read only in the project directory mode; the exported program skips the comparison. To rewrite the files, run `ARCHMAGE_UPDATE_GOLDEN=1 scripts/godot-test.sh --no-sync`. In `../sdk-go`, `go test ./internal -run TestPorting -porting` compares `tests/golden` with the Go golden files as well.
- `tests/atlas_loader_test.gd` tests the loader with the same conf and golden files. `tests/conf/atlas_extension.gd`, which `json-gd` does not regenerate, counts the `on_loaded` calls in `loaded_count` and returns `fail_message`, so that a test can make `on_loaded` fail.
- An async test sets `_use_threads = false` on the loader or the `I18n` to run the path for platforms without thread support; in a build without thread support, it stays `false` for every test, and the tests that check worker threads are skipped. A function that awaits `load_atlas_async()` resumes inside the call that completes the load, which still references the atlas; a test that checks that the atlas is freed awaits a frame first. GDScript does not let a function start a coroutine without awaiting it, so a test that needs a load running in the background starts it with `call_deferred`.

## Conventions

### SDK naming

- `addons/archmage/archmage.gd` declares `class_name Archmage`, the only global class name of the SDK. Other SDK scripts have no `class_name`; `archmage.gd` attaches each as a constant, such as `const Duration = preload("duration.gd")`, and other code refers to `Archmage.Duration`. The path is relative, so the addon can be placed in any directory.
- An SDK script that uses its own type declares it first, such as `const Duration = preload("duration.gd")` inside `duration.gd`. Without it, `-> Duration` fails with `Could not find type "Duration"`.
- `addons/archmage` has no warnings at the default warning levels. In Godot 4.6, `@warning_ignore("integer_division")` on a `func` does not suppress the warnings in its body, so the SDK puts `@warning_ignore_start("integer_division")` before the `##` comment of the first function and `@warning_ignore_restore` after the last. Godot reports no warnings under `res://addons` by default, so to check, use a copy of the project with `debug/gdscript/warnings/directory_rules` set to `{"res://": 0, "res://addons/archmage": 1}` and each warning that is on by default set to 2, and run `godot --headless --editor --quit`.

### Generated config code (`json-gd`)

The template is `archmage/structs/tpls/json-gd.tpl` in `../whisper`. It uses no `--namespace`, and it outputs no `@tool` and no code that affects the runtime; discuss with the user before breaking this. The editor plugin still works with it, because a `@tool` EditorPlugin can call `static func`, `new()` and the methods of a `RefCounted` script without `@tool`.

- When a field name, after the snake_case conversion, is a name that Godot does not allow for a member variable, `json-gd` appends `_` (`class` becomes `class_`), and archmage prints a warning with the field, its source and the new name. The names are the GDScript keywords that are parse errors in Godot 4.6.3 (`var class`, `var func`, `var signal`; `var match` and `var name` are not), plus `int`, `float`, `bool` and `script`. The list is `calc::fieldName` in the template. By the user's decision, `json-gd` handles no other name conflict: a field named `to_json`, or a pubtype named like a native class such as `Timer`, makes the generated file fail to parse.
- Type names follow json-cs: a file-level `class_name` is the top-level type of the config source (`HeroTable`, `GameCfg`), and a private type keeps the prefix of its scope (`Hero_TalentsEntry`). Without the prefix, an inner class could hide a native class (the type of a field `curve` would be named `Curve`) or have the name of a private type of a pubtype in the same file.
- Generated local variables and parameters start with `_` (`_d`, `_x`, `_e1`, `_atlas`), so that they never shadow a field.
- A duration, datetime, minmax or vector field is never `null`: `from_json(null)` returns the zero value, as the value types of Go do. A wtpool or tuple field is `null` when the JSON value is `null`, as the pointers of Go are.
- A ref inside a wtpool or tuple: the SDK object keeps the config ID in `_ref_ids` and `null` in `items`; the generated `_bind_refs` sets `items[i]`, and `_unbind_refs()` of the SDK object sets the ref items back to `null`. `to_json` writes `_ref_ids`.
- A config ID is a plain `int` or `String`. A wrapper object cannot be a `Dictionary` key, because GDScript compares objects by identity.
- A ref field holds the entry, such as `var weapon: ItemTable.ItemCfg`, and is `null` when the ID is the zero value. The ID is `weapon.id`. This works because loading fails when a non-zero ID has no entry.
- `l10n.gd` (`class_name L10n`) is generated when a config has an l10n field. An l10n field is an `L10n` object, as `L10n` is a type in Go and C#. With `ARCHMAGE_GD_STRING_L10N=true`, an l10n field is a `String` that holds the key, and `L10n` has the static functions `text(key)` and `get_text(key, lang)` instead of the property `text` and the method `get_text(lang)`; GDScript does not allow a function and a variable of the same name, so the two modes cannot share one API. This repository generates only the default mode; after a change to the other mode, generate `tests/conf` with `ARCHMAGE_GD_STRING_L10N=true` in a copy of the project and load `tests/testdata`.
- With `ARCHMAGE_GD_FLOAT_DURATION=true`, a duration is a `float` in seconds, which `Archmage.Duration.seconds_from_json` returns. By the user's decision, `to_json` returns the seconds as a number, not the config format, so its output cannot be loaded and the Go golden comparison fails on durations; and `MinMax.sample` draws from a duration range as from any float range, not in whole milliseconds as Go does. This repository generates only the default mode; to check the other, generate `tests/conf` with the variable in a copy of the project and run the tests.
- A lambda that is still in the static `Callable` var `L10n.get_i18n` or `L10n.get_preferred_language` when the process exits makes Godot 4.6.3 abort, so a test that sets a lambda resets the var to `Callable()`, and the docs tell users to set methods or static functions.

### Generated code contract

The SDK side is documented in `addons/archmage/atlas.gd`, `atlas_item.gd` and `parse_error.gd`, and `tests/conf` shows the generated side. These decisions are not stated there:

- `from_json` keeps the ID of a ref in a private field (`_weapon_ref`), and a collection of refs as a collection of IDs of the same shape (`_starter_items_ref`). `to_json` writes these IDs, not the IDs of the entries, so that the output does not change after `unbind_refs` and a nested collection of refs needs no loop that collects the IDs.
- The generated `load_json` of an object that has refs calls `_unbind_refs()` first. Without it, the old entries of an atlas that is loaded again in place reference each other and are never freed.
- By the user's decision, the check for a JSON value of the wrong type adds no work to the success path for each field. For this reason, `load_json` checks `ParseError.mismatched` once per entry, and the message locates only the entry.

### JSON and integers

- The loader parses with `JSON.new().parse()`, not `JSON.parse_string()`, which calls `push_error` on invalid input and returns no error message.
- Godot 4.6.3 parses every number as `float`. The generated code converts an integer with `int(v)`, after it checks that the value is a number; it does not check that the value is integral or in range. README (Limits) documents the loss of precision above 2^53.
- All float values in `tests/testdata` and `tests/override` are exact in float32, so Godot vectors do not break golden comparison. A value such as 0.1 added later needs handling, because the Go porting comparison is strict on float64.

### Error handling

GDScript has no exceptions, so the SDK follows the conventions of the Godot API. The class description of `addons/archmage/atlas_loader.gd` lists the error code of each kind of failure.

- As with `JSON.parse()`, a function that can fail, such as `load_atlas()` or `I18n.merge_l10n_file()`, returns an `Error` code, `OK` on success, and its object returns the message from `get_error_message()`.
- As with `get_node()` and `get_node_or_null()`, `lookup` calls `push_error` with the table name and the ID and returns `null`; `try_lookup` returns `null` without an error.
- Where Go panics, such as `WeightedPool.sample` on an empty pool, the SDK calls `push_error` and returns `null` or `-1`.
- An invalid value, such as `"#FFF"` for rgba, and a JSON value of the wrong type, such as `"abc"` for an int field, fail the load with `ERR_PARSE_ERROR`, as in Go and C#. The message for an invalid value uses Go's wording: `hero[2].themeColor: invalid RGBA string "#FFF"`. The message for a wrong type includes the path of the entry, not of the field: `hero[1]: expected a number, got "abc"`.

### Loading

- `load_atlas_async()` reads, parses and converts on `WorkerThreadPool` and runs BindRefs and OnLoaded on the main thread. Its tasks use only their job objects (`_AtlasFileJob`, `_ItemJob`) and the item's object, and the options that they read are copied when the load starts. The atlas modifier, the logger and the `progress` signal run on the main thread.
- `load_atlas()` and `load_atlas_async()` must both work in Web exports. Without thread support (`OS.has_feature("threads")` is false), the async API loads one item per frame on the main thread; without a `SceneTree`, it loads everything in one call.
- By the user's decision, the SDK does not register texts with `TranslationServer`: l10n keys are config data read through `L10n`, and `tr()` differs from `I18n` (it takes the fallback language from the project settings and treats `""` as missing).

### Editor plugin (`godot-editor-gd`)

- The `sdk-gd` recipe generates it into `addons/archmage_editor/`. It generates `plugin.cfg` and `archmage_editor_plugin.gd` only when they do not exist, so edit those two here; to change the other files, edit `../whisper/archmage/structs/tpls/godot-editor-gd.tpl`. `project.godot` enables the plugin, and the root node of `scenes/main.tscn` (`scenes/main.gd`) exports the config ID properties that it shows as dropdowns.
- The plugin mirrors `godot-editor-cs`. After a fix to one, check whether the other needs it.
- Only `cfg_id_prop.gd` has a `class_name` (`CfgIdProp`), because game code uses it; the editor scripts preload each other, so the plugin adds no other global class to a user's project.
- A single config ID property is marked with `@export_custom(CfgIdProp.HINT, CfgIdProp.HERO)` and has the type `int` or `String`; an array uses `CfgIdProp.HERO_ARRAY` and has the type `Array[int]` or `Array[String]`. `HINT` is `PROPERTY_HINT_NONE`; the array editor of Godot reads the element type from the hint string and passes `PROPERTY_HINT_NONE` and the part after `:` to the editor of each element. Do not use `PROPERTY_HINT_TYPE_STRING`: without the plugin, Godot edits a `String` property with that hint as a class name, and clicking it crashes the editor.
- `_enter_tree` and `_exit_tree` of `archmage_editor_plugin.gd` call `CfgIdInspectorPlugin.rebuild_inspector()`, because the Inspector keeps its property editors when a plugin is enabled or disabled. Call it directly: in the C# plugin, a deferred call ran in `Main::cleanup` when the editor exited and crashed `--import`.
- To check the plugin for warnings, follow the method for the SDK with `"res://addons/archmage_editor": 1` in `directory_rules`, and run `godot --headless --editor`.
- To check the Inspector without the GUI editor, run `godot --headless --editor` with a temporary EditorPlugin that opens `scenes/main.tscn` with `EditorInterface.open_scene_from_path`, selects the root node with `EditorInterface.edit_node`, and inspects the children of `EditorInterface.get_inspector()`. An array property expands after its toggle button is set to pressed and emits `pressed`; each element editor then edits an `EditorPropertyArrayObject` property such as `indices/0`.
